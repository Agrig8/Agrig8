**File**: `scripts/staging-cleanup.sh`

```bash
# Clean expired staging data:
# - Trades older than 30 days
# - Orphaned file uploads older than 7 days
# - Docker images/volumes not in use
# - Test secrets older than 90 days

SQL

# Docker cleanup
docker system prune -af --filter "until=168h"  # 7 days
docker volume prune -f --filter "label=env=staging"

# Secret cleanup (if using external secrets manager)
# AWS Secrets Manager, Vault, etc.
```

### Issue #118: Validate environment example drift
**Summary**: Detect missing or obsolete environment variables between examples and application configuration.

**Primary Area**: `.env examples` and `scripts`

**Current State**:
- `.env.staging.example` exists with 20+ variables
- Backend code references environment variables
- No automated validation that example file is in sync with actual usage

**Problem Scenarios**:
1. **Missing vars**: Backend code uses `NEW_FEATURE_FLAG` but it's not in `.env.staging.example`
2. **Obsolete vars**: `.env.staging.example` has `DEPRECATED_VAR` that's no longer used
3. **Documentation drift**: Variable comments don't match current behavior

**Proposed Changes**:

#### 1. Create Validation Script
**File**: `scripts/validate-env-examples.sh`
```bash
#!/usr/bin/env bash
# Validates that .env examples match actual environment variable usage

set -euo pipefail

EXAMPLE_FILE=".env.staging.example"
SOURCE_DIRS="backend/src"

# Extract vars from example file (ignore comments and blank lines)
EXAMPLE_VARS=$(grep -oP '^\K[A-Z_]+(?==)' "$EXAMPLE_FILE" | sort | uniq)

# Extract vars referenced in code (process.env.VAR_NAME)
CODE_VARS=$(grep -rhP 'process\.env\.\K[A-Z_]+' $SOURCE_DIRS | sort | uniq)

# Find vars in code but not in example
MISSING=$(comm -13 <(echo "$EXAMPLE_VARS") <(echo "$CODE_VARS"))

# Find vars in example but not in code
OBSOLETE=$(comm -23 <(echo "$EXAMPLE_VARS") <(echo "$CODE_VARS"))

EXIT_CODE=0

if [ -n "$MISSING" ]; then
  echo "::error::Missing vars in $EXAMPLE_FILE:"
  echo "$MISSING" | while read var; do
    echo "  - $var"
  done
  EXIT_CODE=1
fi

if [ -n "$OBSOLETE" ]; then
  echo "::warning::Potentially obsolete vars in $EXAMPLE_FILE:"
  echo "$OBSOLETE" | while read var; do
    echo "  - $var"
  done
fi

if [ $EXIT_CODE -eq 0 ]; then
  echo "✓ Environment examples are in sync with code"
fi

exit $EXIT_CODE
```

#### 2. Add to CI Pipeline
Add step to existing CI workflow or create dedicated workflow:
```yaml

- name: Validate environment examples
  run: |
    chmod +x ./scripts/validate-env-examples.sh
    ./scripts/validate-env-examples.sh
```

#### 3. Pre-commit Hook
**File**: `.githooks/pre-commit` (or add to existing)
```bash

# Check env drift before allowing commit

if git diff --cached --name-only | grep -qE '(backend/src/|\.env.*\.example)'; then

      echo "Environment validation failed. Please update .env examples."

    }
  fi
fi
```

### Issue #119: Add deployment lock timeout
**Summary**: Prevent overlapping deployments and report stale or expired deployment locks.

**Primary Area**: `.github/workflows`

**Current State**:
- Staging workflow uses `concurrency` group: `staging-${{ github.workflow }}-${{ github.ref }}`
- `cancel-in-progress: true` cancels old runs
- **No timeout for stuck deployments**
- **No detection of stale locks**

**Problem Scenarios**:
1. Deployment hangs indefinitely (network issue, broken migration)
2. Lock never releases, blocks all future deployments
3. No visibility into lock age or holder

**Proposed Changes**:

#### 1. Add Deployment Lock Mechanism
**File**: `scripts/deployment-lock.sh`
```bash
#!/usr/bin/env bash
# Manages deployment locks with timeout

LOCK_FILE="/tmp/deployment.lock"
LOCK_TIMEOUT_SECONDS=1800  # 30 minutes
LOCK_INFO_FILE="/tmp/deployment.lock.info"

acquire_lock() {
  local deployer="$1"
  local deployment_id="$2"
  
  if [ -f "$LOCK_FILE" ]; then
    local lock_age=$(( $(date +%s) - $(stat -c %Y "$LOCK_FILE") ))
    
    if [ $lock_age -gt $LOCK_TIMEOUT_SECONDS ]; then
      echo "::warning::Stale lock detected (age: ${lock_age}s, timeout: ${LOCK_TIMEOUT_SECONDS}s)"
      echo "Removing stale lock..."
      rm -f "$LOCK_FILE" "$LOCK_INFO_FILE"
    else
      echo "::error::Deployment already in progress"
      if [ -f "$LOCK_INFO_FILE" ]; then
        echo "Lock info:"
        cat "$LOCK_INFO_FILE"
      fi
      return 1
    fi
  fi
  
  # Create lock
  echo "$deployment_id" > "$LOCK_FILE"
  cat > "$LOCK_INFO_FILE" <<EOF
deployer: $deployer
deployment_id: $deployment_id
started_at: $(date -Iseconds)
EOF
  
  echo "✓ Deployment lock acquired"
  return 0
}

release_lock() {
  rm -f "$LOCK_FILE" "$LOCK_INFO_FILE"
  echo "✓ Deployment lock released"
}

check_lock_age() {
  if [ ! -f "$LOCK_FILE" ]; then
    echo "No active deployment lock"
    return 0
  fi
  
  local lock_age=$(( $(date +%s) - $(stat -c %Y "$LOCK_FILE") ))
  echo "Active lock age: ${lock_age}s (timeout: ${LOCK_TIMEOUT_SECONDS}s)"
  
  if [ $lock_age -gt $LOCK_TIMEOUT_SECONDS ]; then
    echo "::warning::Lock has exceeded timeout"
    return 1
  fi
  
  return 0
}

case "${1:-}" in
  acquire)
    acquire_lock "$GITHUB_ACTOR" "$GITHUB_RUN_ID"
    ;;
  release)
    release_lock
    ;;
  check)
    check_lock_age
    ;;
  *)
    echo "Usage: $0 {acquire|release|check}"
    exit 1
    ;;
esac
```
